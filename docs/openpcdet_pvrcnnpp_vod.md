# Frozen PV-RCNN++ downstream evaluation for View-of-Delft

This integration uses the official OpenPCDet `PVRCNNPlusPlus` implementation
as an isolated dependency. No PV-RCNN++ model code is copied into this
repository. The detector is trained once on clean VoD training point clouds,
selected on clean VoD validation 3D mAP, frozen, and reused unchanged for
clean/faulty/coarse/fine evaluation.

## Data contracts

- Clean VoD points are `[x, y, z, reflectivity]`. The measured reflectivity is
  passed to OpenPCDet's `intensity` slot; it is not synthesized.
- Boxes are geometric-centre LiDAR boxes
  `[x, y, z, dx(length), dy(width), dz(height), heading]` generated by the
  existing calibrated VoD annotation loader.
- The detector ROI is the thesis ROI: `x=[0,64)`, `y=[-32,32)`. OpenPCDet uses
  0.10m XY detector voxels while reconstruction remains on its 0.20m grid.
- Repaired point clouds preserve every faulty point outside the repair mask,
  remove every faulty point inside it, and append one deterministic pseudo
  point for each reconstructed occupied cell. Its Z is decoded P90 height and
  its reflectivity is copied from the nearest preserved measurement.
- Coarse and fine call the exact same `repair_point_cloud` function.

The public VoD test split has no GT labels. Quantitative AP on public data must
therefore use `val`, or `test` only with a separately authorized label root.

## 1. Install isolated upstream OpenPCDet

Run on Linux in the detector environment. The checker prints PyTorch, CUDA,
GPU compute capability, `nvcc`, and spconv before any build:

```bash
cd /workspace/sensor-fusion-fault-localization
python tools/openpcdet/check_openpcdet_environment.py
bash tools/openpcdet/bootstrap_openpcdet.sh
```

The bootstrap selects `spconv-cu126>=2.3.8` on Python 3.12+ and
`spconv-cu120>=2.3` on older supported Python versions. Override it when your
audited PyTorch/CUDA environment requires another official spconv 2.x wheel,
for example
`SPCONV_PACKAGE=spconv-cu118 bash tools/openpcdet/bootstrap_openpcdet.sh`.

The bootstrap pins official OpenPCDet commit
`233f849829b6ac19afb8af8837a0246890908755`. On an RTX 5090, verify that the
installed PyTorch build exposes the GPU compute capability before compiling.

## 2. Export clean VoD and create official CustomDataset infos

```bash
python tools/openpcdet/export_vod_clean.py \
  --vod-root /workspace/view_of_delft_PUBLIC \
  --output-root /workspace/openpcdet_vod_clean

python tools/openpcdet/create_vod_infos.py \
  --openpcdet-root third_party/OpenPCDet \
  --data-root /workspace/openpcdet_vod_clean \
  --dataset-config configs/openpcdet/pv_rcnn_plusplus_vod.yaml \
  --workers 8
```

## 3. Train once on clean train and freeze the best validation checkpoint

```bash
python tools/openpcdet/train_vod_pvrcnnpp.py \
  --openpcdet-root third_party/OpenPCDet \
  --config configs/openpcdet/pv_rcnn_plusplus_vod.yaml \
  --data-root /workspace/openpcdet_vod_clean \
  --output-root /workspace/vod_pvrcnnpp_clean \
  --batch-size 2 --workers 8 --epochs 80
```

If the upstream output layout differs, add
`--checkpoint-dir third_party/OpenPCDet/output/.../ckpt`; selection remains
based only on clean validation 3D mAP.

`best_validation_map.pth` is the only checkpoint used downstream. Neither
reconstruction outputs nor test annotations enter detector training or model
selection.

## 4. Export four point-cloud conditions

```bash
python tools/openpcdet/export_reconstruction_conditions.py \
  --vod-root /workspace/view_of_delft_PUBLIC \
  --data-root /workspace/reconstruction_vod_radar3_unique_multibox_selector \
  --radar-root /workspace/radar20_pointpillars_cache \
  --coarse-checkpoint /workspace/COARSE_RUN/best_model.pt \
  --fine-checkpoint /workspace/FINE_RUN/best_model.pt \
  --selector-config configs/coarse_reconstruction_vod_pointpillars_hrnet_halo_recall_weighted_unlimited_pillars_dropout010.json \
  --output-root /workspace/vod_pvrcnnpp_conditions \
  --split val --device cuda --batch-size 2 --num-workers 8
```

## 5. Evaluate the same frozen detector

```bash
python tools/openpcdet/evaluate_reconstruction_pvrcnnpp.py \
  --openpcdet-root third_party/OpenPCDet \
  --config configs/openpcdet/pv_rcnn_plusplus_vod.yaml \
  --detector-checkpoint /workspace/vod_pvrcnnpp_clean/best_validation_map.pth \
  --conditions-root /workspace/vod_pvrcnnpp_conditions \
  --vod-root /workspace/view_of_delft_PUBLIC \
  --output-root /workspace/vod_pvrcnnpp_reconstruction_eval \
  --split val --batch-size 2 --workers 8 \
  --iou-threshold 0.5 --visualize-samples 50
```

Outputs include official KITTI-style BEV/3D AP from OpenPCDet, supplementary
class-wise rotated-BEV TP/FP/FN/precision/recall/F1/matched IoU, condition AP
deltas, object recovery, per-frame predictions, per-object matches, JSON/CSV
summaries, and four-panel BEV visualizations.
